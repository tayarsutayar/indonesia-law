# 06 — REST API and Realtime

## 1. Conventions

- Base path `/api`, JSON, OpenAPI generated by FastAPI; the frontend generates its TypeScript client and enums from it (`openapi-typescript`).
- Auth v1.0: `Authorization: Bearer <APP_STATIC_TOKEN>` on every route, including WebSocket (token in the first message, not the URL). No route is unauthenticated except `GET /api/health`.
- Pagination: cursor-based (`?cursor=…&limit=…`, max 200) for lists and logs.
- Errors: `{"error": {"code": "string", "message": "string", "details": {}}}` with proper HTTP status. Messages are Indonesian for UI display; `code` is stable English for programs.
- Dates: ISO `YYYY-MM-DD`; timestamps ISO 8601 UTC; the UI renders in WIB (Asia/Jakarta) with Indonesian month names.
- All mutating endpoints write an `event_log` entry with actor and payload.

## 2. Endpoints

| Group | Endpoints |
|---|---|
| Health | `GET /api/health` (per dependency) |
| Search | `GET /api/search?q=&jenis=&tahun=&status=&scope=works|nodes&at=` (metadata + full text, highlights offsets, never altered text) |
| Works | `GET /api/works`, `GET /api/works/{id}`, `GET /api/works/{id}/pdf?manifestation=`, `GET /api/works/{id}/status`, `GET /api/works/{id}/source-text` |
| Nodes | `GET /api/works/{id}/tree?at=YYYY-MM-DD`, `GET /api/nodes/{node_id}`, `GET /api/nodes/{node_id}/history` |
| Versions | `GET /api/works/{id}/versions`, `GET /api/works/{id}/diff?from=&to=`, `GET /api/works/{id}/consolidated?at=` |
| Relations | `GET /api/works/{id}/relations`, `GET /api/graph?center=&depth=&types=` |
| Review | `GET /api/review-queue?reason=&status=&age=`, `GET /api/review/{id}`, `POST /api/review/{id}/claim`, `POST /api/review/{id}/decisions` |
| Control | `POST /api/runs` (scope), `POST /api/runs/{id}/estimate`, `POST /api/runs/{id}/start|pause|resume|stop`, `POST /api/runs/{id}/retry-failed`, `POST /api/works/{id}/rerun?stage=`, `GET|PUT /api/auto-mode`, `GET|PUT /api/swarms/{category}`, `POST /api/uploads` (single PDF/URL) |
| Observability | `GET /api/logs`, `GET /api/works/{id}/trace`, `GET /api/llm-calls`, `GET /api/llm-calls/{id}` (request/response), `GET /api/metrics/{summary|coverage|tokens|swarm|quality|scraping|versioning}?group_by=&from=&to=`, `GET /api/export/{tokens|logs}.csv` |
| Agents | `GET /api/agents` (instances + state, for the office "no animation" table) |
| Realtime | `WS /ws/events` |

Review decisions use the `review_decision` model (`03` §2.4). The API validates that `reject` and `return_to_stage` carry a reason, and that `manual_transcription` passes the Verbatim Verifier against the reviewer's transcription before it is accepted.

## 3. WebSocket Events

Client subscribes with filters: `{"type":"subscribe","run_id":…,"work_id":…,"categories":[…]}`.

| Event | Payload (main fields) |
|---|---|
| `agent.spawned` / `agent.retired` | agent_id, category |
| `agent.state_changed` | agent_id, state, task_id |
| `task.started` / `task.finished` / `task.failed` | task_id, work_id, stage, duration_ms, error |
| `llm.call` | agent_id, work_id, prompt_id, tokens, cost_usd, latency_ms |
| `llm.throttled` | deployment, retry_after_ms |
| `doc.status_changed` | work_id, from, to |
| `qc.result` | work_id, tier, passed, routed_to |
| `review.created` / `review.resolved` | review_item_id, reason |
| `budget.warning` | scope, used_pct |
| `domain.throttled` / `domain.paused` | domain, delay_ms, reason |
| `run.state_changed` | run_id, status |

Rules: events carry a monotonically increasing `seq`; on reconnect the client sends `last_seq` and the server replays from `event_log`. Office View and Dashboard are **event consumers only**; no business logic in the frontend. Rate: the server batches high-volume events (`llm.call`) at most every 250 ms per subscriber.
